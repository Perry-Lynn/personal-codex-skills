# Model Router

将开发任务推进到有证据的完成状态，采用以下角色：

| 角色 | 默认模型 | 默认推理强度 | 职责 |
| --- | --- | --- | --- |
| Planner | gpt-6-astra | low | 需求、代码与架构分析、方案、影响范围、重新规划 |
| Executor | gpt-5.6-luna | high | 修改、调试、编译、测试、验证 |

## 指定模型与角色

先从用户请求解析本轮 Routing Profile：

```text
Planner:  {model: <planner-model>, reasoning_effort: <planner-effort>}
Executor: {model: <executor-model>, reasoning_effort: <executor-effort>}
```

用户可以指定模型、推理强度，或明确交换 Planner/Executor 的职责。只指定一侧时，另一侧沿用默认值；完全未指定时使用 Astra low → Luna high。模型和强度必须传给实际委派工具支持的对应字段，不能声称仅凭提示完成切换。若宿主不支持用户指定的组合，报告阻塞，不静默降级。

## 真实路由与能力边界

先检查当前实际暴露的子 Agent 工具、模型覆盖参数和支持的模型/强度。技能文字不能更改当前会话模型，也不能证明模型已经切换。不要修改全局 config.toml、创建用户可见新任务或运行嵌套 Codex 来模拟路由。

本技能明确请求在宿主规则允许时使用子 Agent，并指定上述模型与强度。所有委派仍须满足宿主对独立、有界子任务和并行工作的限制；若只能串行处理且宿主不允许此类委派，执行下面的降级路径。主 Agent 始终负责协调、汇总和结果审查，子 Agent 不再递归委派。

当 collaboration.spawn_agent 可用且允许所需委派时：

- Planner 使用 Routing Profile 中的 model 和 reasoning_effort；默认是 model="gpt-6-astra"、reasoning_effort="low"。
- Executor 使用 Routing Profile 中的 model 和 reasoning_effort；默认是 model="gpt-5.6-luna"、reasoning_effort="high"。
- 指定模型覆盖时使用 fork_turns="none" 并提供完整的精简交接包；不得用继承全部历史的方式假定覆盖生效。
- 使用返回的 Agent 标识发送补充信息和接收结果。同一角色尽量复用原 Agent；不可对已运行 Agent 静默更改模型。
- 只在主 Agent 同时有独立有用工作时委派，例如子 Agent 规划期间主 Agent 核实验收条件，实施期间主 Agent 审查接口兼容性；不要重复编辑同一文件。
- 其他宿主工具以实际 schema 为准，不照搬参数名，也不虚构已安装的自定义 Agent。

模型/强度不可用、缺少委派工具或宿主不允许委派时，简短告知“当前环境无法执行指定双模型路由，将由当前模型按相同阶段完成”。继续已授权工作，不暗中替换成其他模型。若用户要求必须真实双模型且不接受降级，说明具体缺失能力，停止依赖该能力的工作。

## PLAN → EXECUTE → VERIFY

新功能、多模块修改、API/数据流变化、SDK 集成、复杂 Bug 和性能问题先规划。明确且低影响的局部修复直接执行；配置、安全、隔离等高影响改动不能仅因行数少而跳过分析。用户只要求分析或“先不改代码”时，在计划交付处结束。

Planner 阅读实际代码和项目约束，产出可交接的 Implementation Plan：目标与验收标准、当前实现和代码位置、影响范围、技术方案、拟修改文件、实施步骤、风险、验证方法。只传递结论、证据和可执行步骤，不传递隐藏推理过程。PLAN 默认只读业务文件。方案在用户已授权范围内即可进入实施，不机械要求用户批准计划。

Executor 先对照当前代码复核计划，再实施最小充分修改。实现细节不一致可自主修正；保留 API 契约、业务隔离、用户现有改动和项目风格。一次只指定一个工作者负责同一组可写文件。

交接包必须包含：

- 用户目标、授权边界和验收条件；
- 工作目录、相关项目指令、分支/改动状态和必要代码位置；
- 当前计划或计划修订、可写范围、明确不可动的内容；
- 已执行检查及其结果、待验证事项；
- 返回要求：变更摘要、实际命令与结果、残留风险，以及 DONE / REPLAN / BLOCKED 状态。

验证命令从项目文档、构建脚本和改动风险选择，不机械遍历所有平台。区分静态审查、测试、编译、运行、集成和视觉验收。执行失败时分析日志、定位根因、修复后重跑相关检查；不要重复运行没有新信息的失败命令。普通编译错误、API 实现错误和复杂局部调试仍归 Executor。

## REPLAN

当技术路线不可行、发现核心业务规则、关键接口假设失效，或需要显著扩大修改范围时，Executor 停止扩展修改并返回：反证、现有改动状态、影响和待决策问题。不要撤销用户改动。

由 Planner 修订受影响的计划，再由 Executor 继续。用户范围改变或权限不足时必须保留原授权边界，不能以重新规划扩大权限。若相同阻塞在没有新证据时反复出现，报告阻塞及所需输入，不无限循环。

## 收尾与沟通

主 Agent 检查实际差异及验证证据后再宣布完成，不能仅转述子 Agent 的成功声明。汇报完成内容、核心修改、验证结果和未验证事项。保持必要的进度更新，及时说明影响交付的失败；无需逐次播报路由，但不可隐瞒降级或把未调用的模型说成已调用。
