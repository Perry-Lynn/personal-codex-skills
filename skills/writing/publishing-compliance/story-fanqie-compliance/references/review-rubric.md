# 番茄发布前审查量表

## 证据分级

| 等级 | 含义 | 处置 |
|---|---|---|
| BLOCK | 明确红线或确定性低质阻断 | 修订前不得发布 |
| FIX | 高概率影响审核、推荐或阅读体验 | 修改后复查 |
| REVIEW | 依赖上下文、题材和细节程度 | 人工确认并记录边界 |
| PASS | 本次范围未发现已定义风险 | 不等于平台保证通过 |

## 审查顺序

1. 确认受检文件、平台返回理由、是否授权修改，以及受检文件是否确实属于当前活跃书；独立稿件不得混入当前项目上下文。
2. 运行静态预检，记录确定性信号和 advisory。
3. 人工检查六类平台禁止内容。
4. 人工检查重复拼凑、流水账、突兀转折、人物失真和无意义描写。
5. 对长篇核对上下文、细纲、状态、能力限制、伏笔和章尾承接；对短篇核对小节大纲和情绪推进。
6. 修订时保留剧情功能和角色动机，删除无功能内容，补因果与结果。
7. 运行 story 项目已有的 AI 句式、退化、标点和元信息扫描。
8. 修改影响连续性时提交 revision 追踪事务，再做最终复查。

## 人工检查清单

### 平台硬红线

- [ ] 无违法政策、恐怖极端、民族宗教和现实封建迷信宣传风险。
- [ ] 无淫秽色情、赌博吸毒、犯罪教学和无必要的暴力恐怖渲染。
- [ ] 无未成年人性化、危险模仿诱导或损害身心健康内容。
- [ ] 无隐私泄露、侮辱诽谤、造谣侵权和可识别现实影射。
- [ ] 无广告推广、交易引流、诈骗集资和非法传播。
- [ ] 无人肉网暴、群体攻击、现实号召、平台漏洞和绕审教学。

### 章节质量

- [ ] 章首存在目标、异常、冲突或明确期待。
- [ ] 主角或核心人物作出关键选择，行动改变现场。
- [ ] 本章至少交付结果、代价、信息、关系变化、战果或新问题之一。
- [ ] 转折有来源，人物出场有铺垫，信息与能力不是凭空出现。
- [ ] 无重复段落、百科新闻拼贴、符号乱码、流程日志和无关环境。
- [ ] 章尾落在具体动作、物件、警报、伤口、奖励、选择或新麻烦。

### story 连续性

- [ ] 与细纲和追踪状态一致，没有重复已完成任务。
- [ ] 伤势、装备、冷却、能力上限、人物位置和关系连续。
- [ ] 主角保有关键选择和收益归属，配角没有无声夺走承诺高光。
- [ ] 未提前释放终局底牌，作者秘密没有泄漏给读者视角。
- [ ] 正文无“本章、上一章、细纲、读者、爽点、伏笔、任务卡”等工程元信息。

## 标准报告模板

```markdown
# 番茄发布前审查

- 检查范围：
- 平台反馈：无/具体内容
- 总结论：BLOCK / FIX / REVIEW / PASS
- 静态预检：通过/发现 X 项阻断、Y 项提示

## BLOCK

- 文件:行号｜原文摘要｜风险类别｜为什么阻断｜建议修法

## FIX

- 文件:行号｜问题｜对阅读/推荐的影响｜建议修法

## REVIEW

- 文件:行号｜语境边界｜需要作者确认什么

## 已修改

- 文件｜修改内容｜是否影响连续性｜追踪是否同步

## 最终边界

- 未检查范围：
- 仍需人工确认：
- 结论不构成平台通过保证。
```
