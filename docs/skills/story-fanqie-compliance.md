# story-fanqie-compliance

`story-fanqie-compliance` 是番茄小说发布前专项门禁 skill。它把平台硬红线、现实引流与隐私、恶意水文、故事连续性和去 AI 味前置检查合并成一次可复核流程。

## 适用场景

- 为大纲或章节增加番茄发布边界。
- 发布正文、简介、书评、章评或主页文案前检查风险。
- 根据平台返回的具体拒审理由定位候选问题。
- 保留剧情功能的同时修订风险表达和低质段落。
- 检查重复拼凑、流程日志、突兀转折、人物失真和空洞升华。
- 更新项目中的平台规范与检查流程。

它不能承诺作品一定通过审核或获得推荐。缺少平台具体拒审理由时，只能给出候选风险，不能断言某一段就是命中原因。

## 触发示例

```text
用番茄发布标准审查这篇短篇，只给报告，不改稿。

平台说内容低质，结合拒审截图定位具体问题并给修改方案。

检查简介和前三章有没有引流、隐私、恶意水文或连续性风险。

保留这个反转，修掉可能影响审核的表达，修改后重新检查。
```

## 工作模式

1. **写作前约束**：把平台边界转为本次写作的可执行要求。
2. **发布前审查**：检查正文和发布文案，输出分级证据。
3. **拒审诊断**：优先使用平台返回理由和原文定位风险。
4. **合规修订**：保留人物动机、冲突和爽点，修复风险表达与断裂因果。
5. **规范维护**：保留来源和日期，增量更新项目规则。

## 四道门禁

- **平台硬红线**：法律政策、恐怖极端、淫秽色情、犯罪教学、未成年人、隐私和权利侵害。
- **盈利与平台秩序**：广告营销、交易引流、诈骗集资、人肉网暴、现实攻击和绕审经验。
- **低质与恶意水文**：重复拼凑、乱码、无关环境、空洞升华、流水账、突兀转折和主角失真。
- **故事工程质量**：细纲、连续性、信息来源、能力限制、人物状态、收益归属和章尾承接。

## 结论分级

| 等级 | 含义 |
|---|---|
| `BLOCK` | 明确红线、引流人肉、绕审教学、垃圾行、重复填充或关键连续性破坏，修完前不可标记可发布 |
| `FIX` | 高概率影响审核或推荐的低质、突兀、失真、过度渲染或无结算问题 |
| `REVIEW` | 依赖具体语境的灵异、暴力、交易、现实原型、未成年人或敏感背景 |
| `PASS` | 本次范围未发现已定义风险，不代表平台保证通过 |

## 静态预检脚本

脚本依赖 Python 3，仅使用标准库。

```bash
python3 skills/writing/publishing-compliance/story-fanqie-compliance/scripts/fanqie_preflight.py <file-or-directory>
```

需要机器可读结果时添加 `--json`。返回码：

- `0`：没有发现确定性阻断项。
- `1`：发现阻断项。
- `2`：输入或运行错误。

脚本只识别重复段落、工程词、乱码式行、明显引流和绕审表达等确定性信号；即使返回 `0`，仍需要人工语义审查。扫描项目目录时，若存在 `正文/` 子目录，只扫描该子树；否则按相对路径排除隐藏目录、归档、追踪、设定、大纲、参考资料、对标、拆文库、`reports` 和 `node_modules`。显式点名的 `.md`/`.txt` 文件始终扫描。过滤后没有文件、路径/扩展名/编码读取错误返回 `2`。

## 主要文件

| 文件 | 用途 |
|---|---|
| `SKILL.md` | 核心门禁流程、分级和交付契约 |
| `references/fanqie-policy.md` | 平台内容规范执行摘要和题材边界 |
| `references/review-rubric.md` | 审查证据、报告格式和处置标准 |
| `scripts/fanqie_preflight.py` | 确定性静态预检工具 |

## 规则来源与边界

仓库内的平台规则文件是基于既有材料整理的执行摘要，标注的资料时间为 2025-02-26，不是番茄小说官方文件，也不是实时规则镜像。平台规则可能变化；处理最新审核问题时，应优先核对平台当前官方规则和平台返回的具体理由。
